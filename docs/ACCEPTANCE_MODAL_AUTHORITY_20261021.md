# A-03: invalidate modal wallet approvals on managed authority changes

Affected baseline: PR108 `f642682fa2731a5334facff8515b84d9605aa0dd`, also inherited by PR109/110. Four real native Qt nested-loop reproductions deliver `_managed_denied` while a password dialog is open; Verify/View/Create/Open Spending then construct/start their wallet worker despite `_managed_authenticated=False`. Worker fixtures stop before Core/key/anchor operations. This proves a GUI authority/lifecycle defect, not a demonstrated unauthorized signature or native-custody bypass.

Qt modal prompts run nested event loops. A status timer or a second action could occupy/replace `_worker`, and existing methods trusted readiness from before consent. A denial followed by a new READY state could revive an old approval if only a boolean were checked.

The correction reserves the GUI across the complete confirmation sequence, disables competing controls and timer worker starts, refuses window close and file-drop inspection during that interval, and rechecks current authority immediately after every sensitive prompt. An authority epoch invalidates approvals even if READY returns. Root/Core/WSP selectors and worker/spending-window identity are rechecked. Cancellation and exceptions release GUI exclusion in `finally`; native custody leases and all exact-intent signing/broadcast gates remain independent and unchanged. Stop/file-picker handoffs run synchronously after modal exclusion ends, without queuing an approval for another generation.

Coverage also protects current BIP39 creation and read-only crash preview, which share the same modal/worker boundary. Local-only phrase display and read-only file inspection remain available offline; neither imports/unlocks a wallet. Original WSP, upstream Core, vault/anchor/reservation implementation and automatic-broadcast policy are unchanged.

Validation: original four-subcase native Qt reproducer now passes. Existing40 managed GUI tests pass. Eight additional Qt tests cover password-stage denial across six entry points, denial→READY, reentrant timer/actions/inspection/close, worker/path changes, cancellation/exception cleanup, stable approved actions, BIP39 material cleanup after confirmation loss and synchronous stop/offline inspection. These worker/dialog fixtures are source GUI regressions, not genuine Core acceptance. Linux's existing native xcb test step expands its pattern to include the new module; Windows's existing Fusion pattern and Mac's full suite already include it. No extra workflow/job.

Full source/native Core/final frozen execution and exact artifact provenance must qualify this runtime change on each OS. Physical focus/DPI/Finder/appearance and independent DEV review remain pending. No automatic merge; no owner data/anchors/miners or upstream source touched.
